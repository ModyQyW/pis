# PiS developer documentation

[English](README.md) | [简体中文](README.zh.md)

This directory explains how PiS works, how to develop it, how to test it, and how to release it. Users should read the guide at [https://pis.modyqyw.top](https://pis.modyqyw.top) instead.

PiS is a desktop shell around pi. It does not implement model calls, store credentials, or replace pi data. Read [Architecture and data flow](architecture.md) before you change code.

## Quick start

```sh
git clone https://github.com/ModyQyW/pis.git
cd pis
bun install
bun run dev
```

To debug only the Web UI:

```sh
bun run dev:web
```

Browser mode uses mock data and does not connect to pi.

Before a commit:

```sh
bun run format
bun run check
```

`check` runs Go formatting, build, vet, and tests; Vite+ formatting, lint, and type checks; bridge tests; frontend tests; the frontend build; and the documentation build.

## Documentation rules

- User pages live in `docs-user/en/` and `docs-user/zh/`. Each page has both languages.
- `docs-user/` covers only user-visible behavior. Do not add architecture, development, release, or docs-site deployment there.
- Developer pages live in `docs-dev/`. Each guide has an English `.md` file and a Chinese `.zh.md` file.
- Add a language link at the top of every developer page.
- User screenshots go in `docs-user/public/images/`.
- Developer pages can reference the user screenshots with a relative path.
- Update `docs-user/en/_nav.json`, `docs-user/zh/_nav.json`, and the `_meta.json` files when you add or move a user page.
- User-page links use site paths such as `/guide/install`. Rspress adds the `/zh` prefix for Chinese pages.
- Move a page only after you search the whole repository for the old path.
- Do not create an archive directory. Put current research in `research.md`, tradeoffs in `decisions.md`, and the timeline in `history.md`.
