## ADR-001 — 通过 RPC 与 pi 通信，不用 SDK

**背景。** 我们需要真正的扩展/包/技能兼容性和进程隔离。SDK 只有 TypeScript，且需要重新实现 pi 的资源加载器、认证和扩展 UI bridge。RPC 有文档，在 pi 1.x 内稳定。

**决策。** 每个打开的会话启动 `pi --mode rpc`。通过 stdin/stdout 通信严格 JSONL。按 ID 关联命令。stderr 只作诊断。

**后果。** 现有 pi 扩展的加载方式与 CLI 完全一致。pi 崩溃不会杀死应用。RPC 的 UI 子集是硬限制；我们把它暴露出来。我们依赖已安装的兼容 pi。

**替代方案。** 在随附的 Node 进程中用 SDK（pi-agent-desktop、ThinkRail）；因版本耦合、进程重量和扩展 UI 重复而否决。重新实现 pi（直接否决）。

## ADR-002 — 用 mygo webview 外壳，不用原生 UI

**背景。** 产品需要 Markdown、语法高亮、diff、虚拟化转录、可访问对话框和快速 UI 迭代。mygo 可用约 10 MB 的二进制在系统 webview 中承载 Web 前端，也可用 Go 绘制原生 UI。

**决策。** 使用 mygo 的 webview 窗口，配 Vite/React 前端。使用隐藏的内嵌标题栏和原生菜单。对话框、菜单、通知、shell 集成和窗口装饰使用 mygo 的原生 API。

**后果。** 外壳小，不打包浏览器，可用 Web 生态。总占用包含 WKWebView 辅助进程。必须净化所有渲染的 Markdown，绝不在受信页面加载第三方 HTML。

**替代方案。** mygo 原生 UI（定制 UI 工作太多；没有 Web 生态）；Electron（太重）；Tauri（不是要求的框架）。

## ADR-003 — 每个打开的会话一个 pi 进程，保持存活

**背景。** 用户期待并行聊天和后台工作。pi 会话恢复便宜，冷启动昂贵（带许多扩展时 1.5 秒）。

**决策。** 每个打开的会话启动一个 pi 进程。应用运行期间保持存活。切换聊天从不停止运行。"Sleep" 操作停止一个；关闭应用停止全部。默认最多同时存在 6 个活动会话，并给出明确警告。

**后果。** 内存随打开的会话增长（pi 是重的那部分）。后台完成和审批可用。必须谨慎处理进程退出和恢复。

**替代方案。** 单个活动进程（失去后台工作）；每个工作区一个进程（pi 的一个 RPC 进程没有多会话运行时）。

## ADR-004 — 启动前由应用管理项目信任

**背景。** RPC 模式下 pi 的信任上下文是 `hasUI: false`；项目本地扩展/设置不加载，也不出现提示。已复现。

**决策。** 应用读取 pi 的 `trust.json`，并检测需要信任的资源。未决定且存在资源时，显示原生/Web 信任对话框，列出将加载的内容。持久化应用的决定。仅在受信时传 `--approve`；否则不传。永不写 pi 的 `trust.json`。项目的需信任资源变化时重新提示。

**后果。** 信任显式可见。CLI 中受信的项目被认可；在我们应用中受信的项目不会写回 pi 的存储。信任变化后应用必须重启会话。

## ADR-005 — pi 拥有数据；应用拥有 UI 状态

**背景。** pi 会话 JSONL、认证、模型、设置和包与 CLI 共享。背着 pi 写入有损坏和不兼容风险。

**决策。** 永不写 pi 会话 JSONL、`auth.json`、`models.json` 或 `settings.json`。变更使用 pi 命令（prompt、fork、rename、compact、install、auth）。会话 JSONL 只读作显示缓存。应用状态存在于 `PathUserData`（最近工作区、信任决定、UI 偏好、权限）。

**后果。** CLI 与应用保持兼容。部分操作需要重启会话。关闭进程后通过回收站删除会话。

**替代方案。** 直接编辑 JSONL（脆弱，破坏分支/压缩不变量）；直接写认证（安全和格式风险）。

## ADR-006 — 从 JSONL 快速出转录，pi 为准

**背景。** 243 条消息的会话调用 `get_messages` 返回 566 KB，耗时约 1.5 秒，含 pi 启动。首次绘制等它会显得慢。

**决策。** 打开时，用 Go 读取会话文件的活动分支，立即发送显示转录。并行启动 pi。实时事件更新显示。`get_messages`/`get_state` 校正模型、用量和任何差异。显示缓存永不用于模型上下文。

**后果。** 典型会话的转录绘制低于 150 毫秒。必须实现感知分支/压缩的显示解析，并容忍 pi 启动时的部分数据。差异由 pi 的权威消息纠正。

**替代方案。** 等待 `get_messages`（简单，慢）；仅按需解析（首次滚动慢）。

## ADR-007 — 仅增量流式传输，16 毫秒合并

**背景。** 按 token 发送累积的助手快照，字节和 CPU 都是 O(n²)（PI-Desktop ADR 0242）。token 速率可能超过显示帧率。

**决策。** 在 Go 中按消息和内容块合并 `message_update` 的文本/思考增量，最多每 16 毫秒刷新一次，并在工具事件、消息结束、中止和错误前立即刷新。只发送增量加权威 `message_end`。UI 追加到实时消息，结束时替换。

**后果。** 线上成本线性，渲染平滑，顺序保留。前端必须处理重置/替换事件（提供方重试/编辑）。

**替代方案。** 在渲染器合并（太晚；序列化已发生）；发送完整快照（否决）。

## ADR-008 — 随附 bridge 扩展，带命名空间并由 CLI 加载

**背景。** RPC 缺少树导航、计划模式开关和做审批决定的地方。把我们的逻辑作为项目扩展加载需要信任，还会污染用户的包列表。

**决策。** 交付一个小型 `pis-bridge` pi 扩展，嵌入应用二进制，版本变化时写入应用数据，每个 pi 进程用 `-e` 加载。它注册带命名空间的命令（`pis-navigate`、`pis-plan`），监听 `tool_call` 做审批，通过 `setStatus` 发布用量/状态。永不写 pi 数据。项目信任仍归应用。

**后果。** 填补 RPC 缺口，无需全局安装。bridge 必须在支持的版本范围内跟踪 pi 的扩展 API，功能缺失时优雅降级。

**冲突规则（Q6）。** 命令带 `pis-*` 命名空间；bridge 永不注册 `todo`、`ask_user_question`、`plan` 或 `subagents` 工具/命令。不得删除或重写用户包。检测到现有 plan 命令时，应用将其暴露出来，而不是声称拥有它。

**替代方案。** 安装全局包（可见/持久，难以随应用版本化）；fork pi（无法维护）。

## ADR-009 — 计划模式作为一等应用模式

**背景。** Claude Code/Codex 用户期待计划优先的工作流。pi 设计上省略计划模式；扩展存在，但不是人人都装。

**决策。** 编辑框开关进入计划模式。bridge 扩展把活动工具集切换为只读内置工具（以及已知的只读扩展工具），通过 `before_agent_start` 注入计划指令，阻止变更工具。模型在聊天中写计划。"Approve plan" 退出计划模式并发送执行指令。模式持久化在自定义会话条目中，并反映到 UI。

**后果。** 安全探索和显式批准。Bash 仍强大；计划模式下变更类 bash 命令被拒绝/询问。计划模式不是安全边界；批准和操作系统才是边界。

**冲突规则（Q6）。** 我们的命令是 `pis-plan`，不是 `plan`。如果 `get_commands` 显示已安装的计划模式命令，UI 提供它，而不是假装我们的开关控制它。我们永不禁用其他扩展。

**替代方案。** 无计划模式（能力差距）；单独的规划 agent/模型（重，违背 pi 的单会话模型）。

## ADR-010 — 智能审批，可选且感知扩展

**背景。** pi 没有内置权限。用户可能已运行防护扩展（这台机器有 `cc-safety-net`）。问两次体验差；从不问不安全。

**决策。** 提供三种策略：Smart（默认）、Ask all、Allow all。Smart 自动允许只读工具和工作区内的编辑/写入；对破坏性/工作区外/特权 bash、敏感路径和未知风险工具进行询问。请求保持待定直到回答（不自动拒绝）。授权可以一次或整个会话。检测已知防护扩展，并提供为该配置禁用我们的防护。策略由 pi 内的 `pis-bridge` 执行，不由渲染器执行。

**后果。** 有用安全，无需持续提示。启发式不是沙箱；必须明确记录。用户可以选择退出。不得对现有防护配置重复提示。

**冲突规则（Q6）。** 会话开始时检测已知防护包/命令。存在时，该工作区的应用防护默认关闭，UI 说明哪个防护处于活动状态。启用我们的防护是显式的。我们的 bridge 不阻止其他防护已阻止的调用，也不为同一工具调用重复提示。

**替代方案。** pi 原生自主（无提示）；全部询问（吵）；仅操作系统沙箱（v1 超出范围）。

## ADR-011 — 前端技术栈

**背景。** 我们需要精致、可访问、高性能的 UI，代码库规模适合小团队。

**决策。** React 19 + TypeScript + Vite。Tailwind CSS v4 配设计 token。**Base UI** 原语，用生成的 shadcn 风格组件样式化；AI Elements 的消息/trace/附件/标记组件适配到 Base UI。Zustand 管理会话/UI 状态。`@tanstack/react-virtual` 用于转录，支持动态行测量和固定末端滚动模型。**Streamdown** 渲染 Markdown，配官方 code（Shiki）、KaTeX 数学、CJK 和 Mermaid 插件。`diff` 解析 patch。Lucide 图标。

**后果。** 迭代快，原语可访问，生态好。Markdown 渲染器是懒加载块（1.75 MB，gzip 580 KB），主块 634 KB（gzip 198 KB）。生产构建省略 source map。转录按行 memo 并虚拟化；流式 Markdown 延迟，token 更新不会强制整页重渲染。

**替代方案。** Radix 加第二套原语层（否决：两套设计系统）；手写 Markdown（否决：表格/数学/图表/代码维护）；Svelte/Solid（运行时更小，生态更小）；原生 UI（否决）；Electron 渲染器惯例（不适用）。

## ADR-012 — 本地优先持久化，用 JSON 不用 SQLite

**背景。** 应用状态很小：最近工作区、信任决定、UI 偏好、权限策略、窗口布局。会话历史属于 pi。

**决策。** 应用状态存为 `PathUserData` 下的带版本 JSON 文件，原子写入加文件锁。按文件 mtime/大小缓存会话索引元数据。v1 不依赖数据库。

**后果。** 易检查和备份；不需要迁移框架。这个规模重写整个文件没问题。损坏文件回退到默认值并报告，永不静默覆盖。

**替代方案。** SQLite（为少许收益增加依赖）；pi 的设置（混合应用和 agent 配置）。

## ADR-013 — 性能预算是验收标准

**背景。** "性能优秀"作为形容词不可测试。

**决策。** 预算：

| 指标 | 预算 |
|---|---|
| 窗口可见（热启动） | < 700 ms |
| 1k 条消息会话的首次转录绘制 | < 150 ms |
| 流式 UI 帧成本 | 典型 < 8 ms，不重渲染整个转录 |
| 空闲应用占用（不含 pi） | < 120 MB 物理内存 |
| 空闲 CPU | ~0% |
| 应用包（不含 pi） | < 30 MB |
| 会话切换（有缓存） | < 100 ms |

在交付机器上测量。回归记录在 `testing.zh.md`。

**后果。** 驱动架构（快速 JSONL、增量合并、虚拟化）。先测量再声称。

**替代方案。** "尽力而为"（否决；不可验证）。

## ADR-014 — macOS 优先，跨平台代码

**背景。** 交付机器是 macOS arm64。mygo 支持 macOS、Windows、Linux。三平台完整 QA 不在第一版范围内。

**决策。** 发布并验证 macOS arm64。所有平台特定代码放在小辅助函数后（路径、登录 shell、打开/显示、回收站）。在可行时保持 Windows/Linux 构建可编译，记录为未测试。前端除修饰键外不做 macOS 专属假设。

**后果。** 可信的第一版，不假装做过跨平台 QA。Windows/Linux 后续做加固。

## ADR-015 — 默认英文，提供中文 UI

**背景。** 产品开源，目标不止一个用户；需求方写中文。Claude Code/Codex 以英文优先。

**决策。** 默认发布英文，并在设置中提供中文语言（`zh`）。主外壳/对话框字符串放在 `lib/i18n.ts`，以英文源文本为键，用 `t()` 查找和 `{name}` 占位符。根组件订阅语言变化，避免非 React memoization 冻结文案。原生外壳/更新器语言通过 `mygo.App.SetLocale` 跟随同一设置。应用名 "PiS"（仓库 `pis`）。

**后果。** 中文用户得到翻译后的外壳、设置、引导、MCP/worktree 管理器和扩展对话框。工具输出、服务器名、模型名和代码保持工具产生的原样。macOS 原生菜单标签保持英文。字典是增量的；新的英文文案安全回退。

**替代方案。** 中文优先（更窄）；仅英文硬编码字符串（后续 i18n 昂贵）；完整消息目录构建步骤（多一个语言过于复杂）。

## ADR-016 — 用 AI Elements 和 shadcn 统一一套视觉系统，不用两套

**背景。** 第一版 UI 是一组定制 React 组件。看起来协调，但重新实现了消息气泡、附件、折叠、菜单、对话框和 toast，且不支持 Markdown 表格/数学/Mermaid。在手写层旁加入 shadcn 注册表组件会形成两套设计系统并重复原语。

**决策。** 在 Base UI 之上采用 shadcn 生成的组件面，并用 AI Elements 组合消息、气泡、trace、附件和标记。保持一套 token 词汇：应用前景（`fg`）、次要文本（`subtle`）、三级文本（`faint`）；shadcn 的 `muted` 是表面，永不用于文本。用 Streamdown 渲染正文，配官方 code（Shiki）、数学、CJK 和 Mermaid 插件。只在承载产品特定行为的地方保留定制表面（工具卡片、diff 视图、审批坞、变更面板）。

**后果。** 可访问性和焦点行为一致；定制组件更少。生成的注册表文件是应用代码，按应用代码审查。Markdown 块及其官方插件依赖是懒加载；Shiki 语法块按需加载。不使用 `components.json`，因为组件是复制而非构建时生成。

**替代方案。** 保留定制层（代码更多，可访问性更弱）；Radix（Base UI 旁第二套原语运行时）；替换所有组件包括工具卡片（会抹掉产品特定的密度和行为）。

## ADR-017 — 转录用 TanStack Virtual；直接依赖锁定最新精确版本

**背景。** 转录使用动态高度行：Markdown 表格、代码块、工具输出、图片和流式文本在挂载后改变高度。`react-virtuoso` 能处理，但项目统一用 TanStack 做虚拟化，且需要移除该依赖。仓库直接依赖锁定精确版本，且没有 git 历史。

**决策。** 用 `@tanstack/react-virtual` 配 `useVirtualizer`：`measureElement` 处理动态行高，`getItemKey` 绑定转录 ID，`overscan: 8`，`paddingStart`/`paddingEnd` 替代旧的页眉/页脚间距。读者未滚走时保持固定在末尾；`ResizeObserver` 捕捉迟到的 Markdown/Shiki/图片增长。追加行用 `followOnAppend: "smooth"`；最后一行的内容增长在布局后滚动。向上滚超过 100 px 解除固定并显示跳到最新按钮。

直接依赖在 `package.json` 中锁定精确版本；lockfile 提交。更新直接依赖会更新 lockfile，并要求 typecheck、测试、生产构建和相关浏览器表面检查。KaTeX 仅因其 CSS 作为直接依赖，而 `@streamdown/math` 解析自己的 KaTeX；接受双版本拆分，因为两者渲染正确，且数学是浏览器冒烟测试的一部分。

**后果。** 转录只渲染可见窗口加 overscan（300 行测试台：挂载 16 行，底部距离 0），长会话不再挂载每一行。应用保留现有流式行为，不再用 Virtuoso。包不再包含 `react-virtuoso`。

**替代方案。** 保留 Virtuoso（否决：要求移除且有两套虚拟化栈）；手写窗口化（否决：动态测量和滚动锚定难以可靠）；固定高度行（破坏 Markdown、图片和工具输出）。

## ADR-018 — 代码和 Mermaid 使用官方 Streamdown 插件

**背景。** Markdown 表面需要语法高亮和 Mermaid 图表。PiS 曾为 Mermaid 包装 Pele，并考虑定制 Shiki 高亮器以减少语言块。Streamdown 已发布受支持的 `@streamdown/code` 和 `@streamdown/mermaid` 插件，带懒加载语法、控件、错误处理和经过测试的集成面。维护自定义渲染器重复这些工作，并在样式和流式行为上漂移。

**决策。** 在 Streamdown 的 `plugins` map 中直接使用 `@streamdown/code` 和 `@streamdown/mermaid`。不要将 Pele 或 Shiki 导入应用代码，也不要维护自定义代码高亮器。只为插件容器保留应用级 token 样式。像以前一样使用 `createMathPlugin({ singleDollarTextMath: true })` 和 `@streamdown/cjk`。

**后果。** Markdown 依赖是懒加载；代码语法是懒加载块，仅在出现语言时获取，Mermaid 仅在出现图表时加载渲染器。包包含官方插件资源，而不是手工裁剪的语法集；这是受支持的优化边界。不要通过 fork 插件或删除语法块来"优化"，那会破坏任意代码围栏。移除 Pele 也移除了它的主题桥接和自定义错误回退。

**替代方案。** 保留 Pele 加 `@streamdown/code`（两套图表/高亮栈）；自定义 Shiki 高亮器（语法集更小但不受支持，代码更多）；无高亮（可读性更差）。

## ADR-019 — 转录中加载远程 Markdown 图片

**背景。** 助手输出和导入的会话可能包含 Markdown 图片。Streamdown 加固原始 HTML、`javascript:` 链接、`data:` 图片和 `file:` 图片，但会直接加载 `http(s)` 和协议相对图片源。阻止它们会破坏用户期待看到的截图、图表和提供方托管的图片；代理它们会给桌面应用增加网络服务。

**决策。** 保留远程图片加载。不加图片代理或逐图提示。链接仍需点击，因为应用拦截锚点导航，但图片不是链接。`data:` 和 `file:` 图片仍被渲染器阻止；工具和附件图片是独立的、受信的 `data:` 元素。

**后果。** 模型回复或来自另一台机器的转录可以让 webview 请求远程 URL，这会暴露用户 IP，并可探测机器可达的服务（例如 `http://127.0.0.1:...`）。这是接受的可用性权衡，不是沙箱保证。需要严格网络边界的用户必须使用操作系统、容器或 VM。更改渲染器前，在此记录新的图片行为。

**替代方案。** 阻止远程图片（破坏常见截图和提供方 URL）；代理所有图片（新服务和攻击面）；把图片渲染为链接（每张图多一次点击）。

## ADR-020 — 从 GUI 写入 pi 配置

**背景。** PiS 通过运行 pi 继承模型、提供商、技能、扩展、包和 MCP 服务器，但用户只能看到会话中已经显示的部分。修改默认值、添加兼容提供商或检查已发现的资源，只能编辑 pi 的 JSON 文件或运行 pi 的终端 `config` 界面。旧边界规定 PiS 永不写入 pi 的模型配置。用户要求在应用内完成同样的配置流程。

**决策。** 允许 PiS 读取 pi 的用户配置，并仅在「pi 配置」对话框中明确保存后写入 `settings.json` 和 `models.json`。`mcp.json` 沿用现有流程。写入是原子的，保留 PiS 未编辑的字段，并且只在用户操作时执行。可编辑默认值、自定义提供商和模型、技能和扩展路径、包来源。包来源只是声明；pi 在会话启动时安装。已保存的提供商密钥写入 `models.json`，不会返回页面；`Inspect` 只报告是否存在密钥。PiS 仍不写 `trust.json`、`auth.json` 或会话内容。

用户级配置的指纹控制确认提示。保存更改会记录新指纹，因此外部修改配置前不会重复提示。

**后果。** 写入边界比以前更宽，必须保持明确：每个新写入都需要用户操作、保留未知字段的合并和测试。项目级声明在信任前只列出，不从 PiS 读取、编辑或遍历；仍在项目信任后加载。自定义提供商密钥在用户输入时经过一次渲染进程。GUI 表单无法避免这一点；密钥不保存在 PiS 设置中，不由 `Inspect` 返回，也不记录日志。

**替代方案。** 保持只读并链接到文件（否决：没有 GUI 配置）；嵌入 pi 的终端 `config` 界面（否决：为一个界面在 webview 中增加终端模拟器）；让用户在应用中编辑 JSON（否决：校验和范围写入更难做对）。
