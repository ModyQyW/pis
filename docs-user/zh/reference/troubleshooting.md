# 故障排查

先检查 pi。大多数问题来自 pi 未安装、版本不兼容或未登录。

## 找不到 pi

在终端执行：

```sh
which pi
pi --version
```

然后检查 PiS 设置中的「pi 可执行文件」。

GUI 应用的 `PATH` 可能与终端不同。最稳妥的做法是填写 pi 的绝对路径，再点击「使用此路径」。

常见路径：

```text
~/.bun/bin/pi
/opt/homebrew/bin/pi
/usr/local/bin/pi
```

## pi 版本不支持

PiS 支持 `pi >= 1.6 < 2`。

版本过旧时，用 pi 的安装方式升级。例如重新运行原来的安装命令，或使用包管理器升级。

升级后，在设置中点击「检查」。

## macOS 提示无法打开

当前构建使用 ad-hoc 签名。

处理步骤：

1. 打开「系统设置」。
2. 进入「隐私与安全性」。
3. 找到 PiS，点击「仍要打开」。

也可以执行：

```sh
xattr -dr com.apple.quarantine "/Applications/PiS.app"
```

只对来自本仓库 Release 的文件这样做。

## Windows 提示未知发布者

当前安装器没有代码签名。

1. 点击「更多信息」。
2. 点击「仍要运行」。
3. 完成安装。

确认下载来源和校验值。安全策略禁止未签名程序时，使用有签名的构建或自行构建。

## 登录失败

检查：

- 提供商 ID 是否正确。
- 网络是否可以访问提供商。
- 是否已有另一个登录终端打开。
- 终端中是否显示了具体错误。

同一时间只能打开一个登录终端。关闭旧窗口后重试。

登录流程由 pi 执行。PiS 不保存凭据，也不修改登录结果。

如果登录窗口无响应：

1. 关闭登录窗口。
2. 打开设置 → pi 配置 →「模型和提供商」，再次点击「登录」。
3. 再次开始登录。

## 没有可用模型

会话区显示「没有可用模型」时：

1. 点击「连接」，完成提供商登录。
2. 打开模型选择器。
3. 点击刷新按钮。

仍然没有模型时，检查 pi 的模型配置和登录状态。参考 [pi 模型文档](https://pi.dev/docs/latest/models)。

## 项目扩展或技能没有加载

通常是因为项目未信任。

1. 检查项目根目录中的 `.pi` 资源。
2. 检查项目根目录和上级目录中的 `.agents/skills`。
3. 打开项目时查看信任对话框。
4. 如果选择了「不信任」，关闭会话。
5. 重新打开项目，选择「信任项目」。
6. 新建会话。

已有会话保持启动时的信任状态。信任改变后，必须重新启动会话。

如果项目根目录或上级目录包含 `.agents/skills`，PiS 也会把它列入信任资源。

## 审批没有出现

检查：

- 设置中的审批策略是否为「全部允许」。
- 是否检测到其他 guard 扩展。
- 当前操作是否在 Smart 的检查范围内。

Smart 是启发式规则。部分命令和扩展工具不会触发审批。

需要每个调用都询问时，选择「全部询问」。
需要关闭内置审批时，取消勾选「使用 PiS 审批」。

## 审批出现得太频繁

检查：

- 是否选择了「全部询问」。
- 是否强制启用了 PiS 审批，同时还有其他 guard。
- 命令是否经常访问工作区外的路径。

可以：

- 切换到「智能」。
- 在审批对话框中选择「本会话内允许」。
- 关闭重复的 guard。

## 计划模式没有阻止修改

计划模式基于规则，不是安全沙箱。

可能的情况：

- 命令通过解释器执行，例如 `python3 -c`。
- 扩展工具没有注册为修改类工具。
- 模型使用了规则未覆盖的命令。

需要严格只读时，使用只读文件系统或容器。

## 会话打不开

检查：

- 项目目录是否存在。
- 会话文件是否还在 pi 的 `sessions/` 目录中。
- pi 是否可以启动。

在项目目录运行 `pi`，确认 pi 自己可以启动并使用模型。

如果会话文件已损坏，尝试从侧边栏打开其他会话，或从备份恢复文件。

## 工具调用失败

工具卡片会显示错误。

常见原因：

- 命令不存在。
- 没有权限。
- 工作目录不存在。
- 网络失败。

展开工具卡片查看完整输出。修复后可以重新发送消息。

## 更新失败

检查：

1. 当前版本是否低于最新 Release。
2. Release 是否公开。
3. 网络是否可以访问 GitHub。
4. 当前平台的更新文件是否存在。
5. macOS 是否再次被 Gatekeeper 拦截。

更新签名使用 Ed25519 密钥。不得手动修改更新文件。

## 设置损坏

1. 退出 PiS。
2. 打开设置中的诊断，记下数据目录。
3. 把数据目录移到备份位置。
4. 重新启动 PiS。

PiS 会创建默认设置。

不得删除 `~/.pi/agent`。它会删除 pi 的会话和登录状态。

## 旧 bridge 文件

PiS 的 bridge 文件位于：

```text
extensions/pis-bridge-<版本>.ts
```

正常升级会删除旧文件。

如果看到多个 bridge 文件：

1. 退出 PiS。
2. 重新启动一次。
3. 检查旧文件是否被删除。

不得手动加载未知扩展。

## 收集诊断

设置中的诊断报告包含：

- 应用版本。
- 平台和架构。
- 数据目录。
- pi 路径和版本。
- 设置加载错误。

复制报告前检查路径是否包含私人信息。

提交 issue 时附上：

- 诊断报告。
- 复现步骤。
- 错误消息。
- 操作系统和 pi 版本。

不得附上凭据、API key 或完整的私有会话。
