# 设置

设置保存在 PiS 的应用数据目录中。修改后立即生效，重启后保留。

打开设置：

1. 点击侧边栏底部的「设置」。
2. 或按 `⌘,`（Windows/Linux 为 `Ctrl+,`）。

![设置面板](/images/settings.png)

## 外观

主题模式有三种：

- 系统：跟随操作系统。
- 浅色。
- 深色。

### 色板

内置四套色板：

- 暖砂（默认）：暖中性表面配琥珀强调。
- 石墨：冷中性表面配钢蓝强调。
- 潮青：冷中性表面配深青强调。
- 纸墨：中性灰表面配近黑强调。

色板同时作用于浅色和深色模式。它改变表面、品牌强调和焦点环；布局和文字大小不变。所有色板的主操作都保持近黑。

![色板选择](/images/zh-palettes.png)

升级后旧设置仍使用暖砂。旧版设置文件没有色板字段时，PiS 也使用暖砂。色板保存在 `settings.json` 的 `palette` 字段，取值为 `amber`、`graphite`、`teal` 或 `ink`。

语言支持 English 和中文。切换语言后，界面文字会更新。原生菜单保持英文。

中文界面示例：

![中文设置面板](/images/zh-settings.png)

「显示原始扩展组件」控制扩展 widget。

- 默认关闭。
- 打开后，输入框上方显示可展开的 widget 区域。
- widget 按终端布局设计，可能占用较多空间。

「桌面通知」控制后台运行结束时的系统通知。

- 可以点击「测试通知」检查权限。
- 系统不允许通知时，开关不会生效。
- 只有 PiS 不在前台时才发送完成通知。

## 文字与输入

「代码字号」影响：

- Markdown 代码块。
- diff 对话框。
- 工具输出。
- 文件预览。
- 登录终端。

默认值是 13 px。可选范围是 10 px 到 20 px。

「界面大小」缩放整个窗口，包括对话框。默认是 100%。

「按 Enter 发送」控制发送键。

- 打开时：Enter 发送，Shift+Enter 换行。
- 关闭时：Enter 换行，`⌘Enter`（Windows/Linux 为 `Ctrl+Enter`）发送。

输入框右下角会显示当前按键提示。

## 提供商

「登录提供商…」打开 pi 的登录终端。

PiS 使用 pi 的凭据存储。它不保留第二份凭据，也不记录登录终端输出。你在 pi 资源中保存的自定义提供商密钥写入 pi 的 `models.json`；PiS 不会再次读取。详见[模型与登录](/guide/models)。

## pi 资源

「模型、提供商、技能…」打开「pi 配置」对话框。它读取 pi 自己的文件并显示：

- 默认提供商、模型和思考级别。
- `models.json` 中的自定义提供商和模型。
- pi 发现的技能和 `settings.json` 中配置的路径。
- 扩展文件、配置路径和包来源。
- `mcp.json` 中的 MCP 服务器。

只有你在此对话框保存更改时，PiS 才写入 pi 的 `settings.json` 和 `models.json`。它保留自己未编辑的字段。信任的项目设置了自己的启动模型时，对话框会显示提示；在该项目中，新会话使用项目值。「MCP 服务器…」打开 MCP 对话框；见 [MCP 服务器](/guide/mcp)。

pi 配置与上次确认时不同，对话框会在启动时打开。检查列表并点击「使用此配置」。

PiS 不写入 pi 的 `auth.json`、`trust.json` 或会话文件。

## pi 可执行文件

PiS 需要 pi 可执行文件。

自动检测顺序：

1. 设置中填写的路径。
2. `PATH`。
3. 常见安装位置：
   - `$BUN_INSTALL/bin/pi`，默认 `~/.bun/bin/pi`
   - Homebrew 目录
   - npm、pnpm 和 Volta 的全局目录
4. 登录 shell 的 `PATH`。

从 Finder 或桌面启动时，PiS 会读取登录 shell 的 `PATH`。这样 bun 或 npm 安装的 pi 脚本可以找到 node。

操作：

- 填写绝对路径后点击「使用此路径」。填入的路径成为唯一来源。
- 点击「检查」重新检测。
- 清空输入框再点击「使用此路径」，恢复自动检测。

状态行显示版本和路径。版本必须在 `pi >= 1.6 < 2`。

路径不能运行时，PiS 显示该路径的错误，不会悄悄换用其他安装。

## 审批

审批策略有三种：智能、全部询问、全部允许。

「使用 PiS 审批」控制内置审批：

- 勾选后，PiS 强制启用内置审批。
- 取消勾选后，PiS 关闭内置审批，适合使用其他 guard。
- 检测到其他 guard 时，内置审批默认关闭。

选择「全部允许」也会关闭内置审批。

详细说明见[信任、审批与计划模式](/guide/approvals)。

## 更新

「检查更新…」立即检查新版本。

PiS 默认每天在后台检查一次。

更新来源是公开的 GitHub Releases。更新归档由 Ed25519 密钥签名。

当前 macOS 构建是 ad-hoc 签名。更新后可能再次需要 Gatekeeper 放行。

## 诊断

诊断区域显示：

- 应用版本。
- 平台和架构。
- 数据目录。
- 设置文件路径。
- pi 路径和版本。
- 设置加载错误。如果有。

诊断不包含 prompt、凭据或会话内容。

按钮：

- 「复制报告」：把诊断信息复制到剪贴板。
- 「显示数据文件夹」：打开 PiS 的应用数据目录。

提交 issue 前检查路径中是否包含私人信息。

## 数据目录

macOS：

```text
~/Library/Application Support/PiS/
```

目录内容：

```text
settings.json           PiS 设置
window-state.json       窗口位置和大小
extensions/             内置 bridge 扩展
```

其他系统的路径以设置中的诊断信息为准。

pi 的数据在 pi 自己的目录中：

```text
~/.pi/agent/
```

PiS 不复制 pi 的会话或凭据。只有你在应用中保存更改时，PiS 才写入 pi 的 `settings.json`、`models.json` 和 `mcp.json`。

PiS 的本地状态还包括：

- `pis:` 前缀的草稿和最近会话。
- 这些数据保存在 WebView 的本地存储中。

## 重置设置

设置损坏时，可以重置：

1. 退出 PiS。
2. 找到数据目录。
3. 把整个目录移到备份位置。
4. 重新启动 PiS。

PiS 会创建新的默认设置。

不得删除 `~/.pi/agent`。删除它会丢失 pi 的会话和登录状态。
