# 信任、审批与计划模式

三个功能控制不同范围：

| 功能 | 控制范围 |
|---|---|
| 项目信任 | 是否加载项目级 pi 资源 |
| 审批 | 单次工具调用是否放行 |
| 计划模式 | 当前会话是否允许修改 |

三者都不能替代系统隔离。

## 项目信任

pi 可以加载项目级资源。这些资源可能包含可执行代码：

- `.pi/settings.json`
- `.pi/mcp.json`
- `.pi/extensions`
- `.pi/skills`
- `.pi/prompts`
- `.pi/themes`
- `.pi/SYSTEM.md`
- `.pi/APPEND_SYSTEM.md`
- 项目根目录或上级目录中的 `.agents/skills`

第一次打开包含这些资源的项目时，PiS 显示信任对话框。

![项目信任对话框](/images/trust.png)

对话框列出检测到的资源。检查路径和内容后，选择：

- 「信任项目」：pi 加载这些资源。
- 「不信任」：pi 跳过这些资源。

PiS 读取 pi 的信任记录，但不会写入。PiS 的决定保存在自己的设置中。

已有会话保持启动时的信任状态。改变信任后，关闭会话并重新打开。

只信任你确认过的项目。扩展和技能可以影响模型行为，扩展还可以运行代码。

## 审批

审批决定单次工具调用是否执行。

PiS 有三种策略：

| 策略 | 行为 |
|---|---|
| Smart | 在破坏性命令、敏感文件和工作区外操作前询问 |
| 所有调用都询问 | 每个需要审批的工具调用都询问 |
| 全部允许 | 不显示内置审批 |

### Smart 检查什么

Smart 检查以下情况：

- 破坏性的 shell 命令，例如递归删除、强制 Git 操作、修改系统、安装软件包。
- 工作区外的路径，包括绝对路径、`../` 相对路径和 `$HOME` 路径。
- 敏感文件，例如 `.env`、SSH 私钥、npm 和 PyPI 凭据、`auth.json`。
- 编辑或写入工作区外的文件。
- 名称像修改类工具的扩展工具。

Smart 是启发式规则。它不覆盖所有命令。脚本解释器可以绕过命令检查，例如：

```sh
python3 -c "open('file.txt', 'w').write('x')"
```

需要强边界时，使用容器、虚拟机、受限用户或 pi 自己的隔离能力。

### 审批对话框

![审批对话框](/images/approval.png)

对话框显示：

- 工具名称。
- 命令或文件路径。
- 触发审批的原因。
- 三个选项。

选项：

| 选项 | 结果 |
|---|---|
| 只允许这一次 | 本次调用放行 |
| 本会话内允许 | 相同操作在本会话内不再询问 |
| 拒绝 | 阻止调用，并把结果返回给模型 |

PiS 不会自动拒绝。没有你的选择，请求会保持等待。

### 其他 guard 扩展

PiS 会检测常见的 guard 扩展，例如 `cc-safety-net`。

检测到其他 guard 时，PiS 默认关闭内置审批。两个 guard 同时启用时，你会看到两次提示。

你可以在设置中强制启用 PiS 审批。两个 guard 同时启用时，每个工具调用可能询问两次。

## 计划模式

计划模式把会话切换为只读探索。

![计划模式](/images/plan.png)

开启方式：

1. 点击输入框下方的「计划」。
2. 按钮显示「计划中」，表示计划模式已开启。

计划模式会：

- 把 pi 的活动工具限制为只读工具。
- 阻止编辑和写入文件。
- 阻止常见的修改类 shell 命令，例如 `git push`、`git stash`、`git rm`、`mv`、`cp`。
- 让模型先输出计划。

关闭计划模式后，pi 恢复原来的工具集合。

计划模式的状态保存在会话中。重新打开会话时，PiS 会恢复计划模式。

### 计划模式的边界

计划模式是工作流保护，不是安全边界。

命令检查基于规则。解释器命令和未知扩展工具可能不受限制。例如 `python3 -c` 可以写文件。

需要严格只读时，使用只读文件系统、容器或受限账户。

### 与其他 plan 命令共存

如果项目已经安装了其他 plan 命令，PiS 会显示那个命令。

点击「计划」时，PiS 把该命令插入输入框，不会控制内置计划模式。

## Markdown 图片

会话中的 Markdown 图片会直接加载，包括 `http(s)` 远程地址。

模型输出或导入的会话可能引用远程图片。加载图片会产生网络请求，可能暴露 IP 地址，也可能访问本机服务。

链接仍然只有点击后才会打开。`data:` 和 `file:` 图片被渲染器阻止。

这是有意的行为，原因见仓库中的 ADR-019。需要严格网络边界时，请使用沙箱。
