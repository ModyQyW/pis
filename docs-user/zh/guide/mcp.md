# MCP 服务器

MCP 是 Model Context Protocol。MCP 服务器可以向 pi 提供额外工具和资源。

PiS 只管理 MCP 配置文件。连接、认证和工具调用都由 pi 完成。

![MCP 服务器对话框](/images/mcp.png)

## 配置文件

pi 读取两个文件：

```text
~/.pi/agent/mcp.json              用户级
<项目>/.pi/mcp.json               项目级
```

规则：

- 项目级条目会覆盖同名的用户级条目。
- 项目级配置只在项目被信任后加载。
- 项目级条目可以只包含 `enabled`、`exposure` 或 `toolExposure`，并继承用户级的连接信息。
- PiS 编辑文件时不删除未知字段。

PiS 不会连接服务器，也不会保存 MCP 凭据。

## 打开对话框

从命令面板或设置打开：

1. 按 `⌘K`。
2. 选择「管理 MCP 服务器…」。
3. 或打开「设置 → pi 配置 → MCP 服务器」，再点击「打开 MCP 服务器」。

「pi 配置」对话框会显示已配置的服务器。「打开 MCP 服务器」按钮打开同一个对话框。没有项目时，它显示用户级服务器。项目级服务器在信任项目前标记为未加载。

对话框需要当前项目。没有项目时，它会提示先打开项目。

## 查看服务器

「已配置」列表显示合并后的服务器。

每个条目显示：

- 名称。
- 来源：`user` 或 `project`。
- 类型：`stdio` 或 `http`。
- 命令和参数，或 URL。
- 描述。
- 启用复选框。
- 删除按钮。

启用复选框会写入定义该服务器的文件：

- 用户级服务器写入用户级 `mcp.json`。
- 项目级服务器写入项目 `mcp.json`。

保存后，需要重新加载会话。也可以在 pi 中运行 `/mcp` 重新连接。

## 添加服务器

对话框底部是添加表单。

字段：

| 字段 | 说明 |
|---|---|
| 服务器名称 | 只能包含字母、数字、`_` 和 `-` |
| 描述 | 可选，帮助模型判断何时使用 |
| 命令 | stdio 服务器要执行的命令 |
| 参数 | 用空格分隔 |
| URL | http 服务器的地址 |
| 项目本地 | 勾选后写入 `.pi/mcp.json` |

填写命令或 URL，二选一。

点击「添加服务器」后：

- 名称重复时，PiS 报错，不覆盖原条目。
- 新条目写入选定的文件。
- PiS 检查 JSON 格式，并原子写入文件。

参数按空格拆分。参数中包含空格时，先添加服务器，再在 `mcp.json` 中修改。

## 高级字段

以下字段需要在 `mcp.json` 中手动编辑：

- 环境变量 `env`。
- HTTP 请求头 `headers`。
- OAuth 配置。
- 超时 `timeout`。
- 工具暴露 `exposure` 和 `toolExposure`。
- 工作目录 `cwd`。

PiS 会保留这些字段。通过对话框修改启用状态或删除其他条目时，不会清空它们。

## 删除服务器

点击条目右侧的删除按钮。

确认后，PiS 从该条目所在的文件中删除条目。

删除不会卸载服务器包。例如 `npx` 下载的包仍在本机缓存中。

## 常见问题

### 项目服务器没有出现

检查项目是否已信任。未信任的项目不会加载 `.pi/mcp.json`。

### 添加后没有工具

1. 重新加载会话。
2. 在 pi 中运行 `/mcp`，检查连接状态。
3. 检查命令是否存在，或 URL 是否可访问。
4. 检查 `mcp.json` 的 JSON 是否有效。

### 服务器启动失败

pi 会在会话中报告错误。检查：

- 命令路径。
- `env` 是否正确。
- 网络和代理设置。
- 服务器自身的日志。

### 名称冲突

名称只能包含字母、数字、`_` 和 `-`。只差 `-` 和 `_` 的名称可能被视为同一个服务器。

使用唯一名称。不得依赖大小写区分。
