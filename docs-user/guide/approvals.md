# 信任、审批与计划模式

这三个功能解决不同问题，不能互相替代。

## 项目信任

pi 支持项目级扩展、技能、设置和其他可执行资源。打开一个陌生项目时，PiS 会先显示资源列表和信任对话框。

- PiS **读取** pi 的 trust 存储，但不会写入。
- 用户的选择保存在 PiS 自己的设置中。
- 未信任的项目不会加载项目级可执行资源。
- 已存在的会话保持它启动时的信任状态；要改变信任范围，需要重新启动会话。

信任不是“这个项目一定安全”的证明，只是允许 pi 按项目配置加载资源。

## 审批

PiS 提供三种策略：

| 策略 | 行为 |
|---|---|
| Smart | 破坏性 shell、敏感文件、工作区外修改前询问 |
| Ask all | 所有需要审批的工具调用都询问 |
| Allow all | 不显示内置审批；工具直接执行 |

审批选项通常包括：

- **Allow once**：只允许这一次。
- **Allow for session**：当前会话内允许同类操作。
- **Deny**：阻止调用并把结果返回给模型。

PiS 不会自动拒绝；没有你的选择，请求会保持等待。检测到其他 guard 扩展（例如 `cc-safety-net`）时，内置审批默认关闭，避免双重提示；可以在设置中强制启用。

### 审批不是沙箱

Smart 审批是启发式规则，不是内核级隔离。需要强边界时，使用容器、虚拟机、受限用户或 pi 自己的隔离能力。

## 计划模式

计划模式把当前会话切成只读探索：

- 修改类工具被阻止。
- 只读工具和受控的 bash 仍可用。
- 模型给出计划；你确认后关闭计划模式，再执行变更。

底层由内置 bridge 扩展的 `/pis-plan` 命令实现。计划模式状态显示在输入框和会话状态中。

如果项目已经安装了其他 plan 命令，PiS 会优先显示那个命令，而不是假装内置计划模式完全控制它。

## 安全边界总结

```text
信任      → 是否允许项目资源加载
审批      → 单次工具调用是否放行
计划模式  → 当前会话是否允许修改
OS/容器   → 真正的隔离边界
```

不要把前三者当成第四者。
