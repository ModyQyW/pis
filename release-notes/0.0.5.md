PiS 0.0.5 fixes finding and loading pi, and adds a manual update check in
Settings.

- Settings has a `Check for updates…` button next to the app version. The
  Help menu item and the daily background check are unchanged.
- A pi path you enter is now authoritative. If that file cannot run, PiS shows
  its error; it no longer reports an unrelated auto-detected path.
- PiS reads the login shell's `PATH` before looking for pi and before starting
  it, so apps opened from Finder can run bun/npm-installed pi scripts that need
  node. `~/.bun/bin/pi` works without launching PiS from a terminal.
- Auto-detection adds `$BUN_INSTALL/bin` (default `~/.bun/bin`) and common
  npm, pnpm, and Volta global locations.
- Missing files, directories, and failing `--version` runs now show distinct
  pi errors.
- `scripts/release.sh` now publishes in one run: it updates the version, runs
  the full check, commits, tags, pushes, waits for the Release workflow,
  verifies the draft assets, and publishes the release. `scripts/release.sh
  build` keeps the local build flow used by CI.

macOS builds are ad-hoc signed. Windows builds are unsigned. The Linux archive includes `install.sh`.

Full Changelog: https://github.com/ModyQyW/pis/compare/v0.0.4...v0.0.5
