# UX and visual direction

Status: proposed. The goal is a calm, fast, native-feeling coding agent, not an
IDE and not a chat toy.

## Principles

1. **The work is the interface.** The transcript, tool activity, and resulting
   changes dominate. Chrome recedes.
2. **One primary action per state.** Send, stop, answer, approve, or choose.
   Never present competing primary buttons.
3. **State is always legible.** Which project, session, model, mode, run state,
   and pending input are visible without opening a menu.
4. **No surprise interruptions.** Streaming does not steal scroll; dialogs queue;
   approvals stay pending; background completions notify instead of stealing
   focus.
5. **Fast is a feature.** No spinners for local operations; skeletons only for
   real waits; transitions under 200 ms; no layout jump while text streams.
6. **Native where it counts.** Traffic lights, menus, shortcuts, notifications,
   file dialogs, trash, and window restoration. Web only where it buys richness.
7. **Honest limits.** TUI-only extension UI, unsigned builds, untested platforms,
   and heuristics are stated in the UI/docs, not hidden.

## Layout

```
┌───────────────┬──────────────────────────────────────────────┬───────────────┐
│ sidebar       │ top bar: project / session / run state        │ right panel   │
│  new chat     │                                              │  Changes      │
│  projects     │  transcript (centered column, max 860 px)     │  Files        │
│   sessions    │                                              │  (collapsible)│
│  settings     │                                              │               │
│               │  interaction dock (question/approval/plan)    │               │
│               │  composer (model, mode, context, send)        │               │
└───────────────┴──────────────────────────────────────────────┴───────────────┘
```

- Sidebar 280 px default, resizable 220–360, collapsible.
- Right panel 360 px default, collapsible; changes first, files second.
- Chat column max 860 px; code/diff may use the full column.
- Empty home: product mark, "Open a project" / "New chat", recent projects,
  three concrete starter actions. No marketing copy.
- Composer floats at the bottom with a subtle surface; it is not a giant card.
- On narrow windows, the right panel becomes a sheet; sidebar overlays.

## Visual system

- **Type:** system UI (SF Pro on macOS); monospace for code (`SF Mono`,
  `JetBrains Mono`, `Menlo` fallback). Body 13.5–14 px; Markdown prose 13.5 px
  with 1.72 line height; code 12–14 px; labels 9–11.5 px. Density is compact but
  every label must remain readable at 100% scale.
- **Color:** warm neutral surfaces, one accent (amber/orange), semantic green/
  red/yellow. Dark and light are separately tuned, not inverted. No purple
  gradients, no glass everywhere.
- **Surfaces:** layered neutrals with 1 px borders; subtle shadows only for
  floating layers. Tool cards use a quieter surface than messages. shadcn's
  `muted` is a surface token; secondary text is `subtle`, tertiary is `faint`.
- **Density:** comfortable, not airy. Tool rows are compact by default and
  expand on demand.
- **Motion:** 120–180 ms ease-out for panels/popovers; streaming cursor blink;
  no bouncing. Respect `prefers-reduced-motion`.
- **Icons:** Lucide, 16 px in rows, 18 px in toolbars. No emoji as UI icons.

## Component system

- Base UI primitives, styled with shadcn's generated component surface; AI
  Elements composition for messages, bubbles, traces, attachments, and markers.
- Product-specific surfaces stay bespoke: tool cards, diff view, approval dock,
  extension status rail, changes panel. They use the same tokens and densities.
- Markdown is Streamdown: GFM tables, Shiki code, KaTeX math, CJK line breaking,
  and Mermaid through the official code and Mermaid plugins. The plugins own
  their loading and error surfaces; app CSS only aligns container tokens.
- The prompt, approval, and settings dialogs share one visual language; avoid a
  second primitive runtime.
- The right panel has Changes, Files, and Plan. Plan is a quiet checklist with
  completed items struck through and the active item marked "now"; it reads
  pi's todo state, not a second task store.
- MCP and worktree managers are dialogs, not new top-level pages. They show
  source (`user` / `project`) and destructive actions behind confirmation.
- Per-file revert is a hover action with a red confirmation; it is never shown
  for untracked files because there is no HEAD version to restore.

## Transcript

- User messages: right-aligned quiet bubble; hover reveals Copy and Fork from
  here. No avatar or "You" label.
- Assistant: prose in the document column; no avatar; model/usage in hover
  metadata.
- Thinking: collapsed row "Thinking"; expand to read; never dominant.
- Tool calls: one compact row per call with icon, verb, target, status, duration.
  Expanded: output/diff/preview. Errors use the error color and keep the output.
- Diffs: dialog with file header, +/− counts, unified lines, monospace; Copy
  patch and Reveal. Inline tool output stays scrollable within the card.
- Compaction: a divider with summary and token before/after.
- Branch summary: a collapsible note attached to the branch point.
- Images: thumbnail grid in tool cards and user bubbles; open in the file
  preview where applicable.
- Live tail: only the streaming row updates; Markdown rendering is deferred.
  Scroll follows only at bottom.

## Composer

- Multi-line input, auto-grow up to ~40% viewport.
- Bottom toolbar: model chip, thinking chip, plan toggle, context ring, send/
  stop. Attachments and queued messages above the input.
- While running: primary button becomes Stop. Enter queues/steers by default;
  the composer label states "Enter queues · Esc stops". Esc also stops when no
  dialog, menu, or approval is waiting.
- `@` opens file search; `/` opens commands; both keyboard-first.
- Errors from send appear inline above the composer, not as a toast only.

## Interaction dock

A single dock above the composer handles blocking interactions:

- Extension select/confirm/input/editor.
- Approval requests with risk reason and once/session choices.
- Plan approval.
- Ask-user-question (one question at a time in RPC fallback).
- Shows "1 of N" when queued; Esc cancels only when the extension allows it.
- Never auto-denies a local approval. Extension-provided timeouts are shown.

## Status and notifications

- Top bar run state: Idle, Working, Needs input, Error, Sleeping.
- Sidebar session dot: running (animated subtle), needs input (accent), error
  (red), idle (neutral).
- Extension statuses: a compact chip row in a drawer; ANSI stripped; max 6
  visible; overflow menu. Raw TUI widgets are opt-in.
- Background completion/needs-input: native notification only when the window
  is not focused; clicking focuses the session.

## Keyboard

Implemented and tested:

| Keys | Action |
|---|---|
| `⌘N` | New chat |
| `⌘O` | Open project |
| `⌘K` | Command palette |
| `⌘B` | Toggle sidebar |
| `⌘⇧G` | Toggle changes/files panel |
| `⌘,` | Settings |
| `⌘⇧T` | Session tree |
| `⌘⇧M` | Model and thinking |
| `⌘⇧C` | Compact context |
| `Enter` | Send / steer |
| `Shift+Enter` | Newline |
| `Esc` | Stop run; dismiss a focused dialog/menu first |
| `↑`/`↓` + `Enter`/`Tab` | Navigate composer suggestions |

Deferred: transcript find (`⌘F`), focus transcript (`⌘↑`), edit last user
message, and a queued-vs-follow-up mode switch. Do not show these in the UI
until they work.

On Windows/Linux, `⌘` becomes `Ctrl`; document the difference.

## Empty and error states

- No pi: path, detected version, install command, "Locate pi".
- No models: provider list, "Sign in", link to pi providers docs.
- No project: recent projects + open folder.
- No sessions, including a blank live session: three starter prompts tied to
  the project, not generic marketing.
- Process crash: banner with exit code, stderr tail, "Restart session",
  "Diagnostics". Never silently restart a turn with side effects.
- Extension error: toast + diagnostics entry, session keeps running.

## Tone

Short, concrete, no anthropomorphism. "Pi Mygo" is the product; "pi" is the
engine. Say "session", "project", "run", "approval", "plan". Avoid "agent magic",
"supercharge", and marketing adjectives in the UI.
